# J2 public import exports and search

**Implementation awaits successful validation.** The assistant did not run J2 or its tests. The first user pilot stopped before export because the reader rejected mysqldump's plural `LOCK TABLES` control. The reader now recognizes the observed `LOCK TABLES <quoted table> WRITE` and `UNLOCK TABLES` forms without executing them; that fix and its regression tests have not been run. Other unknown statements still fail. Do not treat authored tests as passed tests or source counts as measured export coverage.

J2 reads the existing scholarly SQL edition without executing source SQL, creates an explicit public projection, exports reusable records and builds CPU-only search. It does not call Apertus, change expert transcriptions, download inputs, build the UI or publish data. The code has no required cluster path or GPU dependency.

## Inputs and policy

Place the already acquired `stapferappdb_final.sql.zip` at `data/raw/`, or pass its actual path with `--source`. Its required SHA256 is `68eba6c4a7cc13eb3e0b6239b00a6ee21e2e0996a24de69224c3915480941c97`; the member is `stapferappdb_final_10.5.16.sql`. Different bytes are rejected, not silently admitted with an override.

`core/policy.py` lists every admitted column. Only the exact observed transcription release label `Internet` is admitted. Unknown/null/other labels are excluded and counted. Internal/editorial comment columns, modern contributor records, administration and binary timestamps are not exported or indexed. This is a conservative software projection, not a new legal licence or independent privacy certification.

Original text, nulls, empty strings, spelling and `$`/`@` markers are preserved. Search text is a separate NFC/whitespace-normalized field. Answer-to-school attribution is not inferred: school lists describe the transcription's context, and `antwort_zugehoerig` is retained only as an uninterpreted integer. Missing page mappings remain null. Historical cantons are separate from edition-era/current labels.

## Commands to run yourself

From the repository directory on branch `jean/backend`:

```bash
uv sync --locked
# Optional software tests; these have not been run for this implementation:
uv run --locked pytest -q
```

Start with one public transcription:

```bash
uv run --locked python -m core.dataset_cli build --source data/raw/stapferappdb_final.sql.zip --out data/derived/j2-pilot --transcription-id 16
uv run --locked python -m core.dataset_cli verify --data-dir data/derived/j2-pilot
uv run --locked python -m core.dataset_cli search "Hörndli" --data-dir data/derived/j2-pilot --transcription-id 16
uv run --locked python -m core.dataset_cli lookup stapfer:answer:41 --data-dir data/derived/j2-pilot
```

The pilot parses/audits the whole pinned dump but exports only transcription 16 and its admitted context. The known reference is answer 41, question I.1, original `Hörndli, heist der Ort, wo die $ Schull $$ ist.`, archive `BAR B0 1000/1483, Nr. 1421, fol. 228-229v`. This is the reference to compare after execution, not a result already obtained by J2. The build does not inject this answer into its output.

If the pilot passes, build all eligible records:

```bash
uv run --locked python -m core.dataset_cli build --source data/raw/stapferappdb_final.sql.zip --out data/derived/j2-full
uv run --locked python -m core.dataset_cli verify --data-dir data/derived/j2-full
uv run --locked python -m core.dataset_cli search "Hörndli" --data-dir data/derived/j2-full --transcription-id 16 --question-code I.1
```

All commands use single lines so they work in PowerShell and Unix shells. Output directories must not already exist. Preserve a failed run and choose a new directory for a rerun; there is deliberately no force/overwrite flag.

If `data/derived/j2-pilot` already contains the reported failed attempt, retry with `--out data/derived/j2-pilot-r2` and use that new directory in the following verify/search/lookup commands. Do not remove the original `_FAILED.json` or imply that recognizing one additional control statement establishes full-dump compatibility.

## Outputs and validation

Each requested output directory contains:

```text
documents.jsonl       questions.jsonl       answers.jsonl
schools.jsonl         places.jsonl          teachers.jsonl
school_teachers.jsonl transformations.jsonl answers.tsv
schema.json           public_policy.json    source_manifest.json
validation_report.json search.sqlite3       _SUCCESS.json
```

The TSV is a readable view with JSON-encoded nullable text cells, preserving null versus empty text and embedded newlines. Full structured records are in JSONL. `schema.json` contains local record definitions under `$defs`, not an official organizer format.

The build checks the source pin/counts, selected primary keys, allowlisted UTF-8 text, record schemas, original-to-decoded-source equality, exported text hashes, SQLite foreign keys/integrity, JSONL/SQLite payload agreement, school-context links, TSV coverage and index counts. Raw relationship issues and excluded rows are reported rather than silently presented as successful records. Null/blank answers remain exported but are not searchable passages. Only a completed verified build receives `_SUCCESS.json` with output checksums. Failure leaves `_FAILED.json` and exits nonzero; search refuses an incomplete directory. `verify` rechecks the completed files without a model call.

Read `validation_report.json` for actual raw, eligible, exported, excluded and indexed denominators, quality flags and timings. Those values are unknown until you run it. Search also checks its database checksum against the completion receipt before opening it read-only. A completed import does not certify historical correctness or semantic retrieval quality.

## Search and application connection

`search` supports `--transcription-id`, exact `--place`, historical `--canton-1799`, `--question-code` and `--limit` (1–100). Search words are literal AND terms, not user-supplied SQL/FTS operators. The index uses SQLite `unicode61 remove_diacritics 2`; this does not modify displayed original text. No semantic model, spelling modernization or multilingual paraphrase is provided by this first lexical search.

Set `BERN_DATA_DIR=data/derived/j2-full` in ignored `.env` after the full build, or point it at the pilot for initial integration. `core.service.search_records(query, transcription_id=None)` returns the six-field source cards agreed with the UI. A missing dataset raises a visible error; it is not replaced by a demo answer. `core.search.lookup_source(record_id)` provides exact source lookup. The J3 `answer_question(...)` implementation and pending-execution instructions are in [J3.md](J3.md); implementing it is not a claim of successful inference.

Implementation references: [MySQL string literals](https://dev.mysql.com/doc/refman/8.0/en/string-literals.html) and [SQLite FTS5](https://www.sqlite.org/fts5.html). Neither reference constitutes a test of this implementation.
