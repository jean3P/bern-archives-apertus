# M1: the live evidence explorer

The Gradio screen uses the existing `core.service.answer_question` boundary. No extra frontend, API server, dependency or model is introduced. The five-field response contract, J3 prompts/citation checks and call/retry bounds are unchanged. J4 remains separate; launching this UI does not run its benchmark.

## Launch

From a checkout containing the integration work:

```bash
uv sync --locked
uv run --locked pytest -q tests/ui tests/core/test_answering.py tests/test_contracts.py
uv run --locked python app.py
```

Open `http://127.0.0.1:7860` on the application host. The application binds only loopback, disables Gradio analytics and does not create a public share link. If the application is on another machine, use your approved private connection or SSH tunnel; no particular server is required. Configure `.env` and the completed dataset as described in [setup](SETUP.md) and [dataset instructions](J2.md). Do not expose the service publicly as a shortcut.

## LIVE and DEMO

The screen defaults to **live**. Enter a question and an optional positive whole transcription ID, then press **Ask**. LIVE sends that input to the existing backend. An unavailable backend, invalid response or invalid input produces an error; it never silently substitutes a fixture. Blank scope means no transcription filter, not the last ID used. A fractional or negative ID is rejected rather than rounded.

The answer and original evidence are separate. Original text/markup, record IDs, survey question, transcription and archive reference remain visible; unverified page mappings are not displayed as zero. Any school-attribution limitation stays in the status/explanation. Source values are HTML-escaped.

Select **demo** to use the existing labelled fixture scenarios without model calls. Changing mode clears the old results; the scenario selector is enabled only in DEMO. Starting a request clears old answer/source text, and both nonanswers and errors return an empty answer. An insufficient-evidence response may retain relevant source cards without claiming they answer the question.

## Bounded live acceptance

For the existing development dossier16:

1. LIVE: `According to I.1, what is the place called?` should reach fresh Apertus and return a cited answer whose source viewer shows the original Hörndli passage and answer41.
2. LIVE: `According to I.1, what are the exact GPS coordinates of the classroom?` should decline unsupported precision, with an empty answer and the related source retained.
3. After an answer, submit invalid input such as transcription `-1`; confirm the error clears the old answer/source. This is an input-error check, **not** a simulated model outage. Network-error behavior is separately covered by software fixtures without stopping a real service.
4. Switch to DEMO and back; confirm labels and cleared results, without treating a fixture as acquired model output.

Actual backend runs use the existing unique `runs/answers/` folders with raw requests/replies, packets, citations and summaries. Preserve them; no old J3/J4 result is overwritten. A working UI path is M1 acceptance, not proof of general answer quality or completion of J4's document audit. In particular, the five development coverage/abstention failures remain separate measured work.
